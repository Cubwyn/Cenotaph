RUST SOURCE TREE
==============================================================================

src/
├── main.rs                # Entry point. Creates winit event loop, launches App.
│
├── app.rs                 # winit::ApplicationHandler implementation.
│                          # Owns EngineState. Routes OS/window events into engine.
│
├── core/                  # Engine core. Owns runtime state and orchestrates subsystems.
│   ├── mod.rs             # pub mod engine;
│   └── engine/
│       ├── mod.rs         # pub use state::EngineState;
│       ├── state.rs       # EngineState: owns GPU state and runtime subsystems,
│       │                  # handles resize, update, and render orchestration.
│       ├── update.rs      # Per-frame update: physics step + gameplay updates.
│       ├── loader.rs      # Disk I/O: loads OBJ, GLB, textures, JSON.
│       ├── sync.rs        # Instance buffer rebuild for rendering.
│       ├── validation.rs  # Non-window project content validation.
│       └── asset_catalog.rs  # Scans model assets.
│
├── systems/               # Engine subsystems (not gameplay logic).
│   │                      # Must not depend on game/.
│   ├── mod.rs             # pub mod input, physics, render;
│   ├── input/
│   │   ├── mod.rs         # pub use manager::InputManager;
│   │   └── manager.rs     # Keyboard/mouse event capture and query.
│   ├── physics/
│   │   └── engine.rs      # Rapier3D wrapper: rigid bodies, colliders,
│   │                      # physics pipeline, player movement physics.
│   ├── render/
│   │   ├── mod.rs         # Module root. Exports render subsystems.
│   │   ├── pipeline.rs    # Render pipeline creation (shaders, layouts).
│   │   ├── shader.wgsl    # Main WGSL vertex/fragment shader.
│   │   ├── hud.wgsl       # WGSL shader for HUD overlay.
│   │   ├── mesh.rs        # Mesh data structures (vertices, indices).
│   │   ├── instance.rs    # Instance buffer for prop rendering.
│   │   ├── texture.rs     # Texture loading and GPU upload.
│   │   ├── camera.rs      # Camera state (view/projection matrices).
│   │   ├── lighting.rs    # Light definitions and uniforms.
│   │   ├── hud.rs         # HUD rendering framework (placeholder health/stamina bars).
│   │   └── assets.rs      # Render-specific asset helpers.
│   └── audio/
│       └── mod.rs         # Audio system stub (rodio backend).
│
├── game/                  # Gameplay-owned state and rules.
│   ├── mod.rs             # pub mod combat, enemy, player, progression;
│   ├── combat.rs          # Prototype combat math.
│   ├── enemy.rs           # Baseline enemy runtime/AI rules.
│   ├── player.rs          # PlayerState, HealthState, StaminaState.
│   └── progression.rs     # RunProgress resource and Anchor state.

    │                      # Must not depend on core, systems, or game.
    ├── mod.rs             # pub mod config, world;

==============================================================================
MODULE DEPENDENCY RULES
==============================================================================

1. main.rs → app.rs → core::engine::state
2. core orchestrates systems, data, and game
3. game may depend on data and selected systems APIs
4. systems must not depend on game
5. data must not depend on core, systems, or game

This preserves a no-cycle architecture.

Flow:
  main
    app
      EngineState
        ├── systems::input
        ├── systems::physics
        ├── systems::render
        ├── game::player
        └── data::*          (for config-driven values)

==============================================================================
DATA FLOW
==============================================================================

STARTUP:
  main.rs
    → App::new(level_name)
      → EngineState::new()
        → load tuning.toml  (data::config)
        → load enemy TOML   (data::enemy)
        → load level JSON   (data::world)
        → materialize enemy props from enemy definitions
        → load OBJ/GLB      (core::engine::loader)
        → build GPU buffers (systems::render)
        → build physics     (systems::physics)

FRAME:
  update()
    → physics step
    → EngineState gameplay bridge
      → game::player state
      → game::combat prototype hit math
      → game::enemy baseline chase/attack
      → game::progression resource/Anchor state
      → hurtbox/death/respawn

  render()
    → systems::render

EVENT:
  keyboard/mouse
    → systems::input
    → EngineState gameplay bridge

LEVEL LOAD:
  levels/*.json
    → data/enemies/*.toml materializes enemy props
    → physics/render/combat receive concrete model, collider, and health values

==============================================================================
NAMING CONVENTIONS
==============================================================================

Files:       snake_case.rs
Structs:     PascalCase
Functions:   snake_case
Constants:   SCREAMING_SNAKE_CASE
Modules:     lowercase, one word per file
Types:       prefer semantic suffixes such as State, Config, Data, Id, Type, System

Examples:
  PlayerState
  StaminaConfig
  RelicSuffixId
  BurdenedArchetype

==============================================================================
WHERE THINGS LIVE
==============================================================================

Engine plumbing:       src/core/
Input/Physics/Render:  src/systems/
Gameplay logic:        src/game/
Data definitions:      src/data/
Asset I/O:             src/core/engine/loader.rs
GPU buffers:           src/systems/render/
Configuration:         config/tuning.toml → src/data/config/
Level data:            levels/*.json → src/data/world/
Prop data:             assets/props.json → src/data/world/
3D models:             assets/, levels/
Textures:              textures/

Note on assets/props.json:
  If assets/ is gitignored, ensure .gitignore contains:
    assets/*
    !assets/props.json
  Alternatively, move prop source data to levels/props.json or
  src/data/world/props.json.
