================================================================================
PROJECT OVERVIEW
================================================================================

Cenotaph: The Great Omission is a surreal vertical looter RPG about repeated
ascents through a hostile mountain that changes, forgets, and rewards adaptation.

Current implementation status:
- Rust 2021 single-crate prototype.
- winit application loop.
- wgpu rendering.
- Rapier3D physics.
- rodio-backed audio.
- JSON level data.
- TOML tuning and bindings.
- TOML enemy and relic definitions.
- Foundation gameplay/tooling: movement, jump, sprint, dash, pause, readable
  guided HUD, standalone level editor, in-game quick adjuster, prototype
  shooting with solid-world obstruction, baseline enemy chase/attack, hurtboxes,
  death, respawn, prototype resource pickup/Anchor banking, authored relic
  pickup/reward flow, owned-relic cycling, autosave/resume, basic cycle
  modifiers, and project content validation.

Current north star:
First Ascent Prototype.

================================================================================
RUNTIME COMMANDS
================================================================================

Run default movement/combat sandbox:
  cargo run

Resume autosave:
  cargo run -- continue

Run Ash-Walk:
  cargo run -- ashwalk_01

Run the foundation smoke-test level:
  cargo run -- foundation_test

Run the standalone level editor:
  cargo run -- editor

Validate authored project content:
  cargo run -- validate

Core checks:
  powershell -ExecutionPolicy Bypass -File scripts/foundation_check.ps1
  cargo fmt --check
  cargo clippy -- -D warnings
  cargo test

Manual smoke checks:
  Follow FOUNDATION_SMOKE_CHECKLIST.md after automated checks pass.

================================================================================
CONTENT DIRECTORIES
================================================================================

config/
  bindings.toml
    User-editable keybindings. Current core controls include WASD, Space, Shift,
    Q dash, left mouse attack, Escape pause, debug controls, and in-game level
    editor controls.

  tuning.toml
    Designer-tweakable gameplay constants for player, movement, camera, physics,
    combat, world, lighting, and debug logging.

data/
  enemies/*.toml
    Gameplay-first enemy definitions. Current starter definitions are Ashbound,
    Burdened, Censer, Chainrunner, and Harpy. They reference low-poly enemy
    silhouettes under assets/enemies until production enemy models are generated.

  relics/*.toml
    Authored prototype relic definitions used by level pickups and enemy rewards.

levels/
  ashwalk_01.json
    Current Ash-Walk level shell. Uses assets/ashwalk_001.obj as its base map.

  foundation_test.json
    Foundation smoke-test level. Contains decorative, resource, Anchor, static
    collider, enemy, hurtbox, and transition prop examples.

  ashwalk_001.blend / .obj / .mtl
    Source/exported Ash-Walk level geometry.

assets/
  Cube.obj / Cube.mtl
    Placeholder primitive used by test props.

  enemies/*.obj
    Low-poly authored enemy silhouettes referenced by data/enemies/*.toml.

  ashwalk_001.obj / ashwalk_001.mtl
    Ash-Walk level geometry assets.

  map_001.glb / map_001.blend
    Foundation/default map assets.

  props.json
    Generated model catalog snapshot. Current level placement is driven by
    levels/*.json.

textures/
  Texture directory. PNG/JPG/JPEG files are loaded by filename when present;
  a checkerboard fallback is used when no texture is available.

scripts/
  foundation_check.ps1
    Runs the full non-interactive foundation check: format, clippy, tests, and
    content validation.

================================================================================
SOURCE TREE
================================================================================

src/main.rs
  Entry point. Handles validation/editor CLI arguments and starts the winit app.

src/editor_server.rs
  Localhost level editor server for `cargo run -- editor`, including static
  editor serving, project metadata APIs, level read/save APIs, and Rust-backed
  level validation. Security hardening includes loopback-only bind,
  per-launch tokenized URLs, token-required API calls, local Host/Origin
  checks, path-restricted writes, and backup-before-overwrite saves.

src/app.rs
  winit ApplicationHandler. Owns EngineState and routes window/input events.

src/core/
  Engine orchestration.

src/core/engine/state.rs
  EngineState fields, GPU setup, runtime construction, resize, and rendering.

src/core/engine/update.rs
  Per-frame movement, stamina, dash, gameplay orchestration, hurtbox,
  death/respawn, resource/Anchor checks, debug logging, and transition logic.

src/core/engine/loader.rs
  Asset and texture loading. Handles OBJ/GLB model paths and non-panicking
  fallback behavior.

src/core/engine/sync.rs
  Render instance buffer rebuilds after prop changes.

src/core/engine/asset_catalog.rs
  Scans editor-visible project assets across assets/, textures/, data/,
  levels/, and config/. Separates runtime-supported models from source-only
  model, texture, material, audio, dialogue/data, level, and config files.

src/core/engine/validation.rs
  Non-window content validation for level JSON and core config TOML.

tools/level_editor/
  Standalone browser editor UI: level browser, Hammer-style Camera/Top/Front/Side
  view panels, 3D WebGL viewport, flying camera, ray-picked and orthographic
  select/move/place tools, orthographic marquee and multi-selection, grouped
  transforms with axis and snap controls, transactional undo/redo, floor/wall/
  block/slope/cylinder/stair brushes, placement palette, asset browser,
  configurable keybindings, right-click context menu, group duplicate/copy/
  paste/delete, focus-selected, tabbed prop and level-system inspectors,
  validation navigation, and save controls.

src/data/
  Pure data definitions.

src/data/enemy.rs
  EnemyDefinition loading and validation helpers for data/enemies/*.toml.

src/data/relic.rs
  RelicDefinition loading, ID normalization, value validation, and registry
  lookup helpers for data/relics/*.toml.

src/data/config/gameplay.rs
  GameConfig plus PlayerConfig, MovementConfig, CameraConfig, PhysicsConfig,
  CombatConfig, WorldConfig, LightingConfig, DebugConfig, and keybinding parsing.

src/data/world/level.rs
  LevelData, PropData, ColliderType, level loading, JSON saving, defaults, and
  validation rules.

src/game/
  Gameplay-owned state and rules.

src/game/combat.rs
  Prototype combat math, including ray/sphere enemy target checks for primary
  fire. Solid-world weapon obstruction is queried through the physics wrapper.

src/game/enemy.rs
  Baseline enemy runtime state, chase/attack intent, and attack windup/cooldown
  rules.

src/game/player.rs
  PlayerState, HealthState, StaminaState, dash timers, hit feedback, death, and
  respawn helpers.

src/game/progression.rs
  RunProgress for unsecured resource, banked resource, Anchor activation, local
  Anchor respawn, and death loss rules.

src/game/relic.rs
  Owned relic inventory state, explicit acquisition outcomes, equipped relic
  selection, relic stat modifiers, and cycle-to-next selection rules.

src/game/cycle.rs
  Basic cycle number/modifier state, reward scaling, enemy damage scaling, relic
  damage scaling, and deterministic prototype enemy reward relic IDs.

src/game/editor.rs
  In-game level editor state, placement templates, snapped cursor math, dirty
  state, validation status, reload confirmation, safe deletion, and template
  materialization rules.

src/game/save.rs
  SaveData snapshot/load helpers for level, cycle, resource, Anchor, respawn,
  relic inventory, equipped relic state, fired level events, and level-local
  event flags.

src/game/feedback.rs
  Gameplay feedback timers, event feed entries, camera shake, and HUD flash
  triggers for combat hits, blocked shots, misses, pickups, relics, debug
  actions, healing, and death.

src/systems/
  Engine subsystems.

src/systems/input/
  Keyboard/mouse input capture and query helpers.

src/systems/physics/
  Rapier3D physics wrapper, player movement, coyote-time jumping, prop
  colliders, weapon obstruction ray queries, enemy prop position/velocity
  helpers, path-bound dynamic prop support, and prop removal.

src/systems/render/
  WGPU render pipeline, camera, mesh/model data, instances, textures, lighting,
  HUD, thicker block text, guide strip, editor panel/cursor marker,
  shot-result/event feedback, shaders, and render asset grouping.

src/systems/audio/
  rodio-backed procedural ambient audio, footsteps, one-shot effects, and
  pause/resume behavior.

CURRENT DATA CONTRACTS
================================================================================

Level JSON required fields:
- name
- base_map
- player_spawn
- props

Prop JSON required field:
- asset_id

Prop JSON fields with defaults:
- id
- position
- rotation
- scale
- collider_type
- is_climbable
- is_hurtbox
- item_id
- resource_value
- anchor_id
- enemy_type
- enemy_health
- light_color
- light_intensity
- ambient_sound_id
- trigger_level_id
- loot_table_id
- path_id
- dialogue_id
- event_id

Level JSON authoring collections with defaults:
- asset_imports
- loot_tables
- paths
- events
- dialogues

Validation currently checks:
- level JSON files can be read and parsed
- level name/base_map/player_spawn are usable
- prop assets exist under assets/
- prop transforms are finite
- prop scale does not contain zero
- enemy props do not have negative health
- anchor IDs cannot be empty
- resource pickups cannot also be enemies
- level transitions point at existing level files
- lit props include light color
- authoring graph IDs are stable and unique per collection
- prop loot_table_id/path_id/dialogue_id/event_id references resolve
- asset imports point at real model assets
- loot tables have valid rolls, weights, quantities, and item/resource grants
- loot table item_id values match relic definition IDs
- paths have valid waypoint counts and finite waypoint coordinates
- event triggers/actions include the references required by their kind
- dialogues have speakers and non-empty lines
- enemy definition TOML files parse
- enemy definition IDs are unique
- enemy definitions include a readable visual tell
- level enemy_type values match enemy definition IDs
- runtime level loading fills enemy prop model/collider/health from enemy
  definitions
- enemy activation ranges cannot be smaller than attack ranges
- all model assets under assets/ use supported extensions
- all model assets under assets/ load successfully
- all model assets under assets/ contain render and physics geometry
- tuning.toml parses and uses sane numeric ranges
- bindings.toml has required actions, valid tokens, and no duplicate bindings

ENEMY DESIGN STATUS
================================================================================

Implemented in content:
- Starter enemy definitions now reference role-shaped low-poly silhouettes for
  Ashbound, Burdened, Censer, Chainrunner, and Harpy.
- levels/foundation_test.json and levels/movement_test.json both place all five
  starter enemy archetypes for testing.
- Baseline enemy chase/attack reads activation range, movement, attack range,
  wind-up, damage, and cooldown from enemy definitions.

Gameplay roster direction:
- Ashbound: grunt
- Burdened: tank
- Censer: glass cannon
- Chainrunner: high-speed flanker
- Harpy: aerial threat
- Bellworn: ranged harasser
- Silencer: suppressor
- Paranoiac: escalator
- Anchor Parasite: swarmer
- Root-Machine Hybrid: controller
- Mirror of the Player: late-game duelist
- Bell-Headed: elite modifier frame

See ENEMY_GAMEPLAY_ROSTER.txt and ENEMY_MODEL_GENERATOR_BRIEF.txt.
